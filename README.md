# mission3 - 작은 계산기(Mini NPU 시뮬레이터)

3주차 미션. AI가 하는 MAC(곱하고 더하는) 연산을 파이썬으로 직접 구현하고, 십자가(Cross)와 X 패턴을 판별한다.

## 1. 개요
| 항목 | 내용 |
|---|---|
| 목표 | 3×3부터 25×25까지 패턴을 MAC 연산으로 판정하고, 크기별 연산 시간을 측정 |
| 핵심 | 같은 위치 값끼리 곱해서 모두 더함 (외부 라이브러리 없이 반복문으로 구현) |
| 판정 | 점수가 큰 필터의 라벨. 차이가 `1e-9`보다 작으면 동점(`UNDECIDED`) |

## 2. 환경
| 항목 | 내용 |
|---|---|
| OS | Windows 11 |
| Python | 3.14.10 |
| 편집기 | VS Code |
| 외부 라이브러리 | 사용 안 함 (`json`, `time` 표준 라이브러리만 사용) |

## 3. 실행 방법
```
python main.py
```
실행하면 모드를 고른다. `1`은 사용자 입력(3×3), `2`는 `data.json` 분석이다.

## 4. 구현 내용
- [x] MAC 연산 함수 `mac(pattern, filter_)`
- [x] epsilon(`1e-9`) 기반 점수 비교, 동점은 `UNDECIDED`
- [x] 모드1: 3×3 필터 A, B와 패턴을 한 줄씩(공백 구분) 입력, 형식 오류 시 재입력
- [x] 모드1: 두 점수, 연산 시간(ms), 판정(A / B / 판정 불가) 출력
- [x] 모드2: `data.json`의 `filters`(size_5, size_13, size_25)와 `patterns` 읽기
- [x] 모드2: 키에서 N 추출(`size_13_2` → 13), 필터와 패턴 크기 검증 (불일치는 FAIL로 처리, 프로그램은 계속 실행)
- [x] 라벨 정규화 (`+`, `cross` → `Cross` / `x` → `X`)
- [x] 모드2: 케이스별 판정과 expected 비교 (PASS / FAIL)
- [x] 성능 분석: 크기별 10회 평균 시간(ms)과 연산 횟수(N²) 표
- [x] 결과 요약: 전체 / 통과 / 실패 수, 실패 케이스 목록

## 6. 결과 리포트

### 실패 원인 분석
1. 전체 6개 중 3개가 FAIL이다. 실패한 `size_5_1`, `size_13_2`, `size_25_1`은 모두 판정이 `UNDECIDED`였다.
2. 원인은 데이터/스키마 문제나 로직 문제가 아니라 **두 필터의 점수가 같은 동점**이다. 크기 검증, 키 해석, 라벨 정규화는 6개 모두 통과했다.
3. 예를 들어 `size_5_1`은 입력에 1이 9개이고, X 필터의 값이 모두 0.1이라 X 점수가 0.1×9 = 0.9이다. 십자가 필터는 가운데 값이 0.9라 Cross 점수도 0.9이다. 수학적으로 정확히 같다.
4. 같은 구조로 `size_13_2`는 7.5와 7.5, `size_25_1`은 4.9와 4.9가 나온다. 필터의 가운데 값을 다른 값들의 합과 같게 만든 데이터이다.
5. 그런데 컴퓨터가 계산한 값은 정확히 같지 않았다. `size_5_1`은 Cross `0.9`, X `0.8999999999999999`로 차이가 약 `1.1e-16`이다. 이것이 부동소수점 오차이다.
6. epsilon 없이 `>`로 비교하면 이 차이 때문에 엉뚱한 쪽이 이긴다. `size_5_1`은 Cross, `size_13_2`는 X, `size_25_1`은 Cross가 되어 세 케이스 모두 정답과 반대가 나온다.
7. 그래서 `abs(score_a - score_b) < 1e-9`이면 동점으로 보는 epsilon 정책을 적용했다. 오차는 `1e-16`~`1e-15`로 epsilon보다 훨씬 작아서 동점으로 처리되고 `UNDECIDED`가 나온다.
8. 정답(expected)은 Cross나 X인데 판정이 `UNDECIDED`이므로 FAIL이 된다. 동점이면 `UNDECIDED`로 처리하는 이번 미션의 비교 정책에 따른 결과이다.
9. 나머지 3개(`size_5_2`, `size_13_1`, `size_25_2`)는 두 점수의 차이가 크게 나서 정규화와 epsilon 정책과 상관없이 PASS였다.

### 시간 복잡도 분석
10. N×N 패턴 하나를 MAC 연산하려면 곱셈이 N²번 필요하다. 이중 반복문이 `i`는 N번, `j`는 N번 돌기 때문에 시간 복잡도는 O(N²)이다.
11. 위 표에서 25×25(625번)는 13×13(169번)의 약 3.7배인데, 측정 시간은 0.024810 ÷ 0.007570 ≈ 3.3배로 연산 횟수의 증가와 비슷하게 늘었다.
12. 3×3과 5×5처럼 작은 크기는 시간이 매우 짧아서(약 0.001 ms) 연산 횟수 비율(9→25는 약 2.8배)과 측정 시간 비율(0.00086→0.00168은 약 2배)이 정확히 맞지는 않았다. 시간 값은 실행할 때마다 조금씩 달라진다.
