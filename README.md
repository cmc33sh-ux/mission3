# mission3 - 작은 계산기(Mini NPU 시뮬레이터)

3주차 미션. AI가 하는 MAC(곱하고 더하는) 연산을 파이썬으로 직접 구현하고, 십자가(Cross)와 X 패턴을 판별한다.
**작성 중**이며, 체크 표시(`[x]`)는 구현해서 실제로 실행해 본 것만 한다.

## 1. 개요
| 항목 | 내용 |
|---|---|
| 목표 | 3×3부터 25×25까지 패턴을 MAC 연산으로 판정하고, 크기별 연산 시간을 측정 |
| 핵심 | 같은 위치 값끼리 곱해서 모두 더함 (외부 라이브러리 없이 반복문으로 구현) |
| 판정 | 점수가 큰 필터의 라벨. 동점이면 UNDECIDED |

## 2. 환경
| 항목 | 내용 |
|---|---|
| OS | Windows 11 |
| Python | 3.14.10 |
| 편집기 | VS Code |
| 외부 라이브러리 | 사용 안 함 |

```
python main.py
```
실행하면 모드를 선택한다. (모드 선택 화면은 구현 후 추가)

## 4. 구현 순서 (체크리스트)
- [x] MAC 연산 함수 `mac(pattern, filter_)`
- [x] 두 점수 비교로 Cross / X / UNDECIDED 판정 (기본형)
- [ ] 점수 비교에 epsilon(`1e-9`) 적용
- [ ] 모드1: 3×3 필터 A, B와 패턴을 한 줄씩(공백 구분) 입력, 형식 오류 시 재입력
- [ ] 모드1: 두 점수, 연산 시간(ms), 판정 출력
- [ ] 모드2: `data.json`에서 `filters`(size_5, size_13, size_25)와 `patterns` 읽기
- [ ] 모드2: 키에서 N 추출(`size_13_2` → 13), 필터와 패턴 크기 검증 (불일치는 FAIL로 처리, 프로그램은 종료 안 함)
- [ ] 라벨 정규화 (`+`, `cross` → `Cross` / `x` → `X`)
- [ ] 모드2: 케이스별 판정과 expected 비교 (PASS / FAIL)
- [ ] 성능 분석: 크기별 10회 평균 시간(ms)과 연산 횟수(N²) 표
- [ ] 결과 요약: 전체 / 통과 / 실패 수, 실패 케이스 목록
- [ ] 아래 6번 결과 리포트 작성

## 6. 결과 리포트 (최소 10줄)
구현과 실행이 끝난 뒤 **내 말로** 쓴다. 아래 항목을 모두 다룬다.

1. 실패 케이스가 있었다면 케이스 이름과 원인 (데이터/스키마 문제, 로직 문제, 수치 비교 문제 중 어디인지)
2. 실패가 0개라면 왜 0개가 되었는지 (라벨 정규화, epsilon 정책이 어떻게 작동했는지)
3. 부동소수점 오차가 판정에 준 영향과 epsilon을 쓴 이유
4. 크기가 5, 13, 25로 커질 때 시간이 어떻게 늘었는지 (표의 실제 숫자 인용)
5. 시간 복잡도 O(N²)의 근거 (N이 2배가 되면 연산 횟수가 4배가 되는 이유)
